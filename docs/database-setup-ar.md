# ربط قاعدة البيانات — دليل خطوة بخطوة

هذا الملف يشرح كيف تربط المتجر بقاعدة بيانات حقيقية على الإنترنت.
اتبع الخطوات بالترتيب. لا تحتاج خبرة سابقة.

---

## ليش نحتاج هذا؟

المتجر يحتاج مكانًا يخزن فيه المنتجات والطلبات والزبائن.
هذا المكان اسمه **قاعدة بيانات** (Database)، ونوعها **PostgreSQL**.

حاليًا القاعدة تشتغل داخل جلسة التطوير فقط وتُمسح عند انتهائها.
لتشغيل المتجر فعليًا على الإنترنت، تحتاج قاعدة بيانات دائمة.

---

## الخيار الموصى به: Supabase

مجاني للبداية، سهل، ويوفّر PostgreSQL جاهزة.

### الخطوة ١ — إنشاء حساب

1. افتح: https://supabase.com
2. اضغط **Start your project**
3. سجّل دخول بحساب GitHub (الأسهل) أو بالبريد الإلكتروني

### الخطوة ٢ — إنشاء المشروع

اضغط **New Project**، ثم املأ:

| الحقل                 | شنو تكتب                 | ملاحظة                                        |
| --------------------- | ------------------------ | --------------------------------------------- |
| **Name**              | `mps-production`         | اسم المشروع داخل Supabase                     |
| **Database Password** | كلمة مرور قوية           | ⚠️ **احفظها فورًا** — ما راح تشوفها مرة ثانية |
| **Region**            | `Central EU (Frankfurt)` | الأقرب للعراق من ناحية السرعة                 |
| **Pricing Plan**      | `Free`                   | يكفي للبداية تمامًا                           |

اضغط **Create new project** وانتظر دقيقة تقريبًا.

> **مهم جدًا:** كلمة مرور قاعدة البيانات اكتبها بمكان آمن.
> إذا ضاعت، تقدر تعيد تعيينها من Settings ← Database ← Reset password،
> لكن ساعتها لازم تحدّث الرابط في كل مكان.

### الخطوة ٣ — نسخ رابط الاتصال

1. من القائمة الجانبية: **Project Settings** (رمز الترس ⚙️)
2. اختر **Database**
3. انزل إلى قسم **Connection string**
4. اختر تبويب **URI**
5. **اختر وضع `Session pooler`** — مهم لأن Next.js يفتح اتصالات كثيرة

راح يظهر رابط بهذا الشكل:

```
postgresql://postgres.abcdefghijk:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
```

6. **بدّل `[YOUR-PASSWORD]`** بكلمة المرور التي حفظتها في الخطوة ٢

### الخطوة ٤ — وضع الرابط في المشروع

في مجلد المشروع، افتح ملف `.env` (إذا ما موجود، انسخ `.env.example` وسمّه `.env`):

```bash
cp .env.example .env
```

ثم ضع القيم:

```env
DATABASE_URL="postgresql://postgres.abcdefghijk:كلمة_مرورك@aws-0-eu-central-1.pooler.supabase.com:5432/postgres"

BETTER_AUTH_SECRET="..."
BETTER_AUTH_URL="https://your-domain.com"
NEXT_PUBLIC_APP_URL="https://your-domain.com"
```

**لتوليد `BETTER_AUTH_SECRET`** نفّذ هذا الأمر وانسخ الناتج:

```bash
openssl rand -base64 32
```

> ⚠️ **ملف `.env` ما يُرفع على GitHub أبدًا.** هو محمي مسبقًا في `.gitignore`.
> لا تنسخ محتواه في أي رسالة أو محادثة.

### الخطوة ٥ — إنشاء الجداول

```bash
pnpm db:deploy
```

هذا الأمر ينشئ كل الجداول في قاعدة البيانات الجديدة. ينفّذ مرة واحدة.

للتأكد أنها اشتغلت، افتح Supabase ← **Table Editor** — لازم تشوف الجداول.

### الخطوة ٦ — بيانات البداية

```bash
pnpm db:seed
```

⚠️ هذا يضيف **بيانات تجريبية** (منتجات وهمية للتجربة).
إذا كنت تشتغل على المتجر الحقيقي، **لا تنفّذه** — أضف منتجاتك من لوحة الإدارة.

السكربت يرفض العمل تلقائيًا إذا كان `NODE_ENV=production`، حماية لك.

## البديل: Neon

إذا فضّلت Neon بدل Supabase:

1. https://neon.tech ← **Sign up**
2. **Create project** ← الاسم `mps-production` ← Region: `Europe (Frankfurt)`
3. انسخ **Connection string** من الصفحة الرئيسية
4. تأكد أنه ينتهي بـ `?sslmode=require`
5. كمّل من **الخطوة ٤** أعلاه

Neon يوقف القاعدة تلقائيًا عند عدم الاستخدام (يوفّر لكن أول طلب يكون أبطأ).
Supabase أنسب لمتجر يشتغل باستمرار.

## ملخّص الأسماء داخل النظام

| الاسم                | شنو يعني                       | وين يُستخدم      |
| -------------------- | ------------------------------ | ---------------- |
| `DATABASE_URL`       | رابط الاتصال بقاعدة البيانات   | ملف `.env`       |
| `BETTER_AUTH_SECRET` | مفتاح تشفير جلسات الدخول       | ملف `.env`       |
| `BETTER_AUTH_URL`    | رابط الموقع الكامل             | ملف `.env`       |
| `mps-production`     | اسم المشروع في Supabase        | لوحة Supabase    |
| `postgres`           | اسم قاعدة البيانات الافتراضي   | داخل الرابط      |
| `Session pooler`     | وضع الاتصال المناسب لـ Next.js | إعدادات Supabase |

## مشاكل شائعة

| المشكلة                          | السبب                       | الحل                                         |
| -------------------------------- | --------------------------- | -------------------------------------------- |
| `Can't reach database server`    | الرابط غلط أو القاعدة نائمة | تأكد من الرابط، وافتح لوحة Supabase لإيقاظها |
| `password authentication failed` | كلمة المرور غلط في الرابط   | تأكد أنك بدّلت `[YOUR-PASSWORD]` فعليًا      |
| `too many connections`           | تستخدم الاتصال المباشر      | بدّل إلى **Session pooler**                  |
| `relation does not exist`        | الجداول ما انعملت           | نفّذ `pnpm db:deploy`                        |

---

## أوامر تحتاجها

```bash
pnpm db:deploy    # إنشاء/تحديث الجداول (الإنتاج)
pnpm db:migrate   # إنشاء تعديل جديد (التطوير فقط)
pnpm db:studio    # فتح واجهة لتصفح البيانات
pnpm db:seed      # بيانات تجريبية (التطوير فقط)
```

---

## قاعدة أمان أخيرة

🔴 **لا تضع كلمة مرور قاعدة البيانات أو `BETTER_AUTH_SECRET` في:**

- رسالة أو محادثة
- ملف يُرفع على GitHub
- لقطة شاشة

إذا انكشف أحدها، غيّره فورًا من لوحة Supabase.
